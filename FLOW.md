# Жизненный цикл деплоя (v1, headless)

## Структура на сервере

- **Production**: `/data/apps/<app>/` (`docker-compose.yml`, локальные volumes).
- **Development**: `/data/apps/<app>-dev/` (полностью изолированный dev-стек).

Секреты и переменные окружения не сохраняются на диске сервера: они передаются только в память процесса на время запуска контейнеров.

## Сценарий Dev: push в основную ветку

1. **Репозиторий проекта**:
   - Сборка Docker-образа и публикация в `ghcr.io/wlgdev/<app>` с тегом коммита (короткий SHA).
   - Вызов экшена `wlgdev/deploy/.github/actions/deploy@main` (`is_dev: 'true'`).
2. **Отправка запроса**:
   - Экшен отправляет `workflow_dispatch` в `wlgdev/deploy` и переходит в режим ожидания.
3. **Центральный пайплайн (`deploy.yml`)**:
   - Валидация входных параметров (принадлежность к `wlgdev`, regex-проверка имени, корректность SHA, валидация формата `target`).
   - Скачивание репозитория проекта на указанном коммите.
   - Если задан `target`: генерация `docker-compose.override.yml` с лейблами Traefik (LetsEncrypt, HTTPS-редирект, Host-правило).
   - Подключение по SSH к серверу под пользователем `deploy`.
   - Создание директории `/data/apps/<app>-dev`.
   - Загрузка `docker-compose.yml.new` и атомарная замена на `docker-compose.yml`.
   - Если передан `target`: загрузка `docker-compose.override.yml.new` → `mv` в `docker-compose.override.yml`, создание Docker-сети `proxy-<app>-dev-network` и подключение к ней контейнера `coolify-proxy`.
   - Если `target` не передан: удаление `docker-compose.override.yml` (чистый headless-деплой).
   - Экспорт переменных окружения в текущую сессию.
   - Выполнение `docker compose pull && docker compose up -d --remove-orphans && docker image prune -f`.
4. **Завершение**:
   - Экшен в проекте получает статус завершения и выводит ссылку на центральный лог. Прод-стек остаётся нетронутым.

## Сценарий Prod: публикация релиза

- Запускается по событию `release: [published]`.
- Передаётся параметр `is_dev: 'false'`.
- Тег образа автоматически выставляется равным имени релиза.
- Развёртывание происходит в директорию `/data/apps/<app>/`.

## Ручной перезапуск и откат (Rollback)

Для отката на предыдущую стабильную версию:
1. Открыть вкладку **Actions** в репозитории `wlgdev/deploy`.
2. Выбрать workflow **deploy** и нажать **Run workflow**.
3. Указать репозиторий, полный SHA желаемого коммита и окружение (`is_dev`).
   *(Docker-образ с этим SHA должен существовать в реестре).*

## Обработка сбоев и безопасность

- **Ошибочные параметры**: пайплайн останавливается на этапе валидации, сервер не затрагивается.
- **Обрыв сети при передаче compose**: файл передаётся во временный `.new`, рабочий файл не повреждается.
- **Ошибка при pull**: текущие контейнеры продолжают работать на предыдущей версии образа.
- **Конкурентные деплои**: вызовы для одного и того же стека сериализуются с помощью `concurrency`.
- **Ротация SSH-ключа**: генерация пары → добавление публичного ключа в `~/.ssh/authorized_keys` на сервере → обновление секрета `DEPLOY_SSH_KEY` → тестовый деплой → удаление старого публичного ключа.
- **Ротация PAT**: перевыпуск токена в GitHub → обновление секрета в репозитории.
