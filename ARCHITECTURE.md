# Архитектура централизованного деплоя wlgdev (v1)

Централизованная система автоматического развёртывания headless-сервисов (ботов, воркеров, бэкендов без входящего веб-трафика) для организации `wlgdev`.

## Компоненты системы

```text
wlgdev/deploy (Центральный репозиторий)
├── .github/actions/deploy/action.yml  # Composite Action для вызова из клиентских репозиториев
├── .github/workflows/deploy.yml       # Центральный workflow: валидация, checkout, SSH-деплой
└── scripts/check-server.sh            # Скрипт проверки готовности сервера

Репозиторий проекта                    # Клиент: сборка Docker-образа и запуск Action
Целевой сервер                         # Docker host: пользователь deploy, директории /data/apps/<app>[-dev]
```

## Ключевые решения

- **`workflow_dispatch` вместо `workflow_call`**:
  `workflow_call` выполняется в контексте вызывающего репозитория, что делает недоступными секреты инфраструктуры. `workflow_dispatch` запускается в доверенном контексте центрального репозитория и позволяет выполнять ручной перезапуск или откат на любой коммит через веб-интерфейс GitHub.
- **Интегрированный Composite Action**:
  Клиентские проекты подключают готовый экшен `wlgdev/deploy/.github/actions/deploy@main`. Экшен инициирует деплой, опрашивает статус центрального запуска и возвращает реальный результат деплоя со ссылкой на логи.
- **Изоляция секретов (Least Privilege)**:
  Сервисные репозитории не имеют доступа к SSH-ключам и хостам сервера. Им выдаётся только ограниченный токен с правами на запуск workflow в `wlgdev/deploy`.
- **Разделение окружений**:
  Стеки изолированы по каталогам: `/data/apps/<app>` для продакшена и `/data/apps/<app>-dev` для dev-версий.
- **Безопасность переменных окружения (Transient env)**:
  Переменные передаются через временный файл `.env.tmp` с правами `600`, экспортируются в текущую bash-сессию на время выполнения команд и сразу удаляются с диска.
- **Атомарность обновлений**:
  Файл конфигурации загружается как `docker-compose.yml.new` и заменяется командой `mv`, что исключает поломку работающего стека при сетевых сбоях.

## Секреты и доступы

### Центральный репозиторий (`wlgdev/deploy`)
- `DEPLOY_SSH_HOST` — IP-адрес или домен сервера.
- `DEPLOY_SSH_PORT` — порт SSH (по умолчанию `22`).
- `DEPLOY_SSH_USER` — пользователь сервера (`deploy`).
- `DEPLOY_SSH_KEY` — приватный SSH-ключ пользователя `deploy`.
- `ORG_READ_PAT` — GitHub Personal Access Token (Classic, область `repo`) для клонирования репозиториев организации.
- `GHCR_USER` (variable) — имя пользователя для доступа к реестру контейнеров.

### Клиентский репозиторий
- `DEPLOY_TRIGGER_PAT` — Fine-grained Personal Access Token с правами `Actions: Read and Write` исключительно к репозиторию `wlgdev/deploy`.
